# ✅ 최종 UX 검사 정책

---

## 1. 검사 이력이 **없음**
- 전체 검사 실행

## 2. 검사 이력이 **일부만 존재**
- **남은 검사만 실행**

## 3. 검사 이력이 **모두 존재**
- 조건 분기:

| 조건 | 처리 방식 |
|------|-----------|
| 모든 이력이 **실패** | 전부 **강제 성공 처리** 가능 |
| 일부 성공 + 일부 실패 | **실패 항목만** 강제 성공 처리, 성공 항목은 유지 |
| 모든 이력이 성공 | 아무 동작도 하지 않음 (또는 무시됨)

---

# 🎯 구현 예시 (C#)

```csharp
foreach (var test in tests)
{
    if (test.Result < 0 && test.Method == Auto) // 실패 + 자동 검사
    {
        test.Result = 1;       // 강제 성공 처리
        test.Method = Force;   // 처리 방법 기록
    }
    // 기존 성공 항목은 유지
}
```

---

# 🔐 설계 의도

- ✅ **성공한 이력은 건드리지 않음** → 품질 신뢰성 유지
- ✅ **실패만 강제 성공** → 수율 보정 가능
- ✅ 사용자가 **예측 가능한 흐름**을 이해할 수 있음

---

# 🧠 기억할 것

- 강제 성공 처리는 오직 `실패한 항목`만 대상
- 기존 성공 데이터를 덮어쓰면 안 됨
- 검사 이력이 1개라도 있으면 무조건 "강제 통과"는 **지양**
