# ✅ 검사 실행 정책 (2025-05-15 기준)

## 🔹 All 검사 버튼 사용 조건

- `All` 버튼은 **오직 검사 이력이 1개도 없을 때만 실행 가능**
- 검사 이력이 하나라도 존재하면, `All` 버튼은 **비활성화**되거나 **경고 표시**됨

---

## 🔸 실행 조건 요약

| 조건 | All 버튼 동작 |
|-------|----------------|
| 검사 이력 0건 | ✅ 전체 검사 실행 가능 |
| 검사 이력 1건 이상 | ❌ 전체 검사 불가능 → 경고 또는 비활성화 |

---

## 🔸 이유 및 목적

- **데이터 보호**: 기존 검사 결과를 실수로 덮어쓰지 않도록 함
- **검사 의미 분리**: All 검사는 오직 **최초 상태 진단용**
- **수정은 명시적**: 이후의 수정은 반드시 **개별 버튼을 통해서만** 가능

---

## 🔸 사용자 안내 (UI Tooltip/Message 예시)

- `All` 버튼에 표시:
  > "전체 검사는 최초 1회만 실행할 수 있습니다. 이후에는 개별 검사만 가능합니다."

- 비활성화 시:
  > "이미 일부 검사 이력이 존재하여 전체 검사는 실행할 수 없습니다."

---

## 🔸 보완 제안

- 관리자 권한으로 All 검사 허용 여부 설정 가능
- 또는 검사 이력을 초기화할 수 있는 별도 기능 제공 (예: Reset 버튼)

---

## 🔸 비교

| 방식 | 특징 | 장점 | 단점 |
|------|------|------|------|
| 항상 All 실행 가능 | 자유도 높음 | 유연함 | 덮어쓰기 실수 가능 |
| All = 무조건 덮어쓰기 | 강제 초기화 | 단순함 | 실수 방지 없음 |
| ✅ 이 제안 | 최초 1회 전용 | 데이터 안전, 명확한 흐름 | UX 설명 필요 |

---

## 🧩 확정 정책 요약

> **All 버튼은 검사 이력이 완전히 없는 경우에만 실행 가능하며, 이후에는 반드시 개별 검사 버튼으로만 결과 수정이 가능합니다.**
